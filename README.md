Практика 2, вариант 4.

## Общее описание

Консольная утилита строит граф зависимостей пакета менеджера `apk`
(Alpine Linux) и показывает его. Готовые средства получения
зависимостей не используются: индекс `APKINDEX.tar.gz` скачивается и
разбирается самой программой.

Возможности:

- прямые и транзитивные зависимости пакета;
- обход графа в глубину без рекурсии, обработка циклов;
- обратные зависимости (кто зависит от пакета);
- тестовый режим: граф из файла, пакеты — заглавные латинские буквы;
- вывод ASCII-дерева;
- текст диаграммы на языке D2, SVG-картинка, открытие в браузере.

Этапы разработки:

1. Прототип CLI: параметры и обработка ошибок.
2. Прямые зависимости из репозитория Alpine.
3. Транзитивный граф, DFS без рекурсии, циклы, тестовый режим.
4. Обратные зависимости.
5. Визуализация: D2, SVG, ASCII-дерево, сравнение с `apk`.

## Параметры командной строки

| Параметр | Описание |
|---|---|
| `--package` | Имя пакета (в тестовом режиме — заглавные латинские буквы). Обязателен. |
| `--repo` | URL репозитория Alpine или путь к файлу графа в тестовом режиме. Обязателен. |
| `--test-mode` | `--repo` — файл с описанием графа вместо URL. |
| `--reverse` | Вывести обратные зависимости. |
| `--ascii-tree` | Дополнительно вывести граф в виде ASCII-дерева. |
| `--visualize` | Построить D2-диаграмму, сохранить `.d2` и `.svg`, открыть картинку. |
| `--output-dir` | Каталог для файлов диаграммы (по умолчанию `output`). |

Коды возврата: `0` — успех, `1` — ошибка данных или диаграммы,
`2` — неверные параметры командной строки.

### Построение графа

В `APKINDEX` у пакета поля: `P` — имя, `V` — версия, `D` — зависимости,
`p` — что пакет предоставляет. Из зависимостей убираются условия версий
(`>=`, `=`, `~`) и конфликты (`!имя`). Виртуальные зависимости
(`so:...`, `cmd:...`, `/bin/sh`) заменяются реальным пакетом по полю `p`.
Если несколько пакетов предоставляют одно имя, выбирается первый в
индексе, а пакет с таким же собственным именем имеет приоритет.
Неразрешённые зависимости и зависимость пакета от себя отбрасываются.

### Обход графа

Обход в глубину выполняется без рекурсии: явный стек итераторов и
список пути. Цикл — это ребро к узлу, который находится на текущем пути.
Он выводится списком, где первый и последний элементы совпадают.

### Обратные зависимости

Граф разворачивается (`reverse_graph`) и обходится тем же алгоритмом.
В выводе цикла используется стрелка `<-`.

### ASCII-дерево

Дерево строится итеративно. Пометки: `(цикл)` — узел уже на текущем
пути, `(см. выше)` — узел уже раскрыт выше.

### D2 и визуализация

Файл `<пакет>.d2` содержит `direction: right`; стартовый узел закрашен
(`#ffe699`). Ребро `"A" -> "B"` означает «A зависит от B»; в режиме
`--reverse` направление ребра сохраняется. Для `--reverse` файлы
называются `<пакет>_reverse.d2` и `.svg`. SVG строит программа `d2`,
затем картинка открывается в браузере.

Установка D2 в Windows (после установки откройте новое окно терминала):

```
winget install terrastruct.d2
```

### Формат файла тестового режима

```
# комментарий
A: B C
B: C
C:
```

Имена — заглавные латинские буквы. Зависимость, не описанная отдельной
строкой, становится листом. Повторное описание пакета — ошибка.
Примеры: `data/graph_simple.txt`, `graph_cycle.txt`,
`graph_complex.txt`, `graph_bad.txt` (с ошибками).

## Запуск и примеры

```
run.bat --package A --repo data\graph_simple.txt --test-mode
run.bat --package A --repo data\graph_cycle.txt --test-mode --ascii-tree
run.bat --package C --repo data\graph_complex.txt --test-mode --reverse
run.bat --package A --repo data\graph_simple.txt --test-mode --visualize
run.bat --package curl --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64/APKINDEX.tar.gz --ascii-tree --visualize
run.bat --package bash --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64/APKINDEX.tar.gz --visualize
run.bat --package boost1.82-libs --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/community/x86_64/APKINDEX.tar.gz --visualize
```

Для Linux и macOS используйте `run.sh`.

## Сравнение с apk

Для сравнения `scripts/compare_apk.bat` запускает в Docker образ
`alpine:3.20` и сохраняет в `output/` результаты `apk info -R`,
`apk dot`, `apk add --simulate` рядом с выводом программы.

| Пакет | `apk dot`: узлы / рёбра | Наш граф: узлы / рёбра |
|---|---|---|
| curl | 22 / 48 | 16 / 33 |
| bash | 11 / 22 | 7 / 9 |
| boost1.82-libs | 62 / 233 | 57 / 219 |

Наш граф целиком входит в граф `apk dot`. Расхождения:

- `apk dot` рисует всех кандидатов для виртуальной зависимости
  (`/bin/sh` — `busybox-binsh`, `dash-binsh`, `yash-binsh`; `icu-data` —
  `icu-data-en`, `icu-data-full`; для curl ещё `libncursesw`
  и `ncurses-terminfo-base`). Программа берёт первого поставщика
  в индексе, поэтому лишних поставщиков и их рёбер нет.
- Красные рёбра `apk dot` — конфликты и `install_if` между
  альтернативными поставщиками, а не циклы.
- В `apk dot` к именам добавлены версии, у рёбер — подписи
  виртуальных зависимостей.
- Прямые зависимости (`apk info -R`) и результат `apk add --simulate`
  для curl и bash совпадают с программой. `apk add` не показывает
  пакеты, уже установленные в базовом образе.
