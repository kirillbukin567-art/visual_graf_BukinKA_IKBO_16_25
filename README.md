# Визуализатор графа зависимостей пакетов (Alpine Linux)

## 1. Общее описание

Консольная утилита на Python для анализа зависимостей пакетов
Alpine Linux (формат менеджера пакетов `apk`). Зависимости берутся
напрямую из индекса репозитория `APKINDEX.tar.gz`: готовые менеджеры
пакетов и сторонние библиотеки не используются, только стандартная
библиотека Python.

Проект разрабатывается поэтапно:

1. Прототип с конфигурацией (параметры командной строки, ошибки).
2. Сбор прямых зависимостей пакета из репозитория.
3. Граф зависимостей с транзитивностью, обход в глубину без
   рекурсии, обработка циклов, тестовый режим.
4. **Текущий этап:** режим обратных зависимостей (`--reverse`).
5. Визуализация: язык D2, ASCII-дерево, сравнение с `apk`.

## 2. Функции и настройки

### Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--package ИМЯ` | имя анализируемого пакета (латиница, цифры, `. _ + -`) |
| `--repo ИСТОЧНИК` | URL репозитория или путь к файлу тестового репозитория |
| `--test-mode` | тестовый режим: `--repo` задаёт путь к файлу графа |
| `--reverse` | обратные зависимости: какие пакеты зависят от заданного |
| `--ascii-tree` | вывод зависимостей ASCII-деревом (этап 5) |

Ошибки параметров, репозитория и файла выводятся в stderr в виде
`Ошибка: ...`, код завершения 1. Некорректные параметры argparse
дают код 2.

### Модули (`src/`)

| Файл | Назначение |
|------|------------|
| `main.py` | точка входа, вывод результата, коды завершения |
| `config.py` | разбор и проверка параметров командной строки |
| `apk_repo.py` | скачивание и разбор индекса Alpine, построение графа |
| `graph.py` | обход графа в глубину без рекурсии, поиск циклов, разворот графа |
| `graph_file.py` | чтение тестового репозитория (файл с графом) |

### Как строится граф для Alpine

1. К URL репозитория добавляется `/APKINDEX.tar.gz` и файл скачивается
   (`urllib`, таймаут 30 с).
2. Архив распаковывается (`tarfile`), берётся текстовый файл `APKINDEX`.
3. Текст делится на блоки (пустая строка), строки блока имеют вид
   `буква:значение`. Имя пакета в поле `P`, зависимости в поле `D`,
   предоставляемые имена (provides) в поле `p`.
4. Токены поля `D` очищаются: условие версии (`>=1.2`, `=1.0`, `<`,
   `>`, `~`) отбрасывается, запреты (`!имя`) пропускаются, повторы
   удаляются.
5. Виртуальные зависимости (`so:libc.musl-x86_64.so.1`, `cmd:...`,
   `/bin/sh`) заменяются реальными пакетами по полю `p`. Если имя
   предоставляют несколько пакетов, берётся первый в индексе.
   Неразрешённые зависимости и зависимость от самого себя
   отбрасываются.

### Обход графа

Транзитивные зависимости ищутся обходом в глубину (DFS) без
рекурсии: вместо вызовов функции используется явный стек итераторов
и список текущего пути. Если очередная зависимость уже лежит на
текущем пути, найден цикл: он запоминается, а обход продолжается.
Каждый пакет посещается один раз, поэтому программа не зацикливается.

### Обратные зависимости (`--reverse`)

Обратные зависимости пакета — это все пакеты, которые зависят от него
прямо или через цепочку других пакетов. Рёбра графа разворачиваются
(`reverse_graph`), после чего тот же обход `traverse` запускается от
заданного пакета на развёрнутом графе. Циклы в этом режиме выводятся
со стрелками `<-`: запись `A <- C <- B <- A` означает «от A зависит C,
от C зависит B, от B зависит A».

### Тестовый репозиторий (`--test-mode`)

Текстовый файл, одна строка на пакет: `ПАКЕТ: ЗАВИСИМОСТЬ ЗАВИСИМОСТЬ`.
Имена пакетов — заглавные латинские буквы. Всё после `#` и пустые
строки игнорируются. Пакет, указанный только как зависимость,
считается пакетом без зависимостей.

```
# Ромб
A: B C
B: D
C: D
D:
```

Готовые примеры в каталоге `data/`: `graph_simple.txt` (без циклов),
`graph_cycle.txt` (цикл), `graph_complex.txt` (два цикла),
`graph_bad.txt` (неверный файл для демонстрации ошибки).

## 3. Сборка и запуск тестов

Сборка не требуется: проект на Python 3 использует только стандартную
библиотеку (нужен Python 3.9 или новее).

Запуск тестов (из корня проекта):

```
py -m unittest discover -s tests -t .
```

В Linux/macOS вместо `py` используется `python3`.

Сценарии проверки:

```
.\scripts\test_errors.bat
.\scripts\test_stage3.bat
.\scripts\test_stage4.bat
```

## 4. Примеры использования

Запуск (Windows: `run.bat`, Linux: `run.sh`, либо напрямую).

Тестовый режим, граф без циклов:

```
py src\main.py --package A --repo data\graph_simple.txt --test-mode
Транзитивные зависимости пакета A: 3
  B
  D
  C
Циклические зависимости: нет
```

Тестовый режим, цикл:

```
py src\main.py --package A --repo data\graph_cycle.txt --test-mode
Транзитивные зависимости пакета A: 2
  B
  C
Циклические зависимости: 1
  A -> B -> C -> A
```

Обратные зависимости (кто зависит от D):

```
py src\main.py --package D --repo data\graph_simple.txt --test-mode --reverse
Обратные зависимости пакета D: 3
  B
  A
  C
Циклические зависимости: нет
```

Обратные зависимости с циклом:

```
py src\main.py --package A --repo data\graph_cycle.txt --test-mode --reverse
Обратные зависимости пакета A: 2
  C
  B
Циклические зависимости: 1
  A <- C <- B <- A
```

Репозиторий Alpine:

```
py src\main.py --package curl --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
py src\main.py --package libcurl --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64 --reverse
```

Пример ошибки:

```
py src\main.py --package no-such-package --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
Ошибка: пакет 'no-such-package' не найден в репозитории
```

scripts/   сценарии проверки
